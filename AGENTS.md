AI agents (and humans) can work on it without breaking things.

## How the CVs are produced (the pipeline)

1. **`rendercv/reactive_resume.json`** is the single source of truth. It is an export
   from the [Reactive Resume](https://rxresu.me) app and contains the full data
   (experience, education, skills, languages, etc.).
2. That data is hand-tailored into **three RenderCV YAML files**
   (`rendercv/*_programmer.yaml`), one per role. Hidden/empty sections are omitted,
   summaries and skill ordering differ per role.
3. The YAML files are rendered to **PDF** with RenderCV. The PDFs are committed to
   `output/pdf/` so GitHub Pages can serve them.

> ⚠️ Editing a PDF directly is pointless — always edit the YAML (or JSON), then
> re-render. The PDFs are generated artifacts.

## Toolchain

- **RenderCV v2.8**, installed via pipx: `~/.local/bin/rendercv`.
- Rendering uses **Typst** under the hood (may download packages on first run).

### Regenerating the PDFs

Run from the repo root. Note that `--pdf-path` is resolved **relative to the input
YAML file** (hence the `../output/pdf/...`), not the current directory:

```sh
for f in unity_gameplay_programmer cpp_engine_programmer gamedev_programmer; do
  rendercv render "rendercv/$f.yaml" \
    --pdf-path "../output/pdf/$f.pdf" \
    --output-folder "/tmp/rendercv-$f" \
    --dont-generate-markdown --dont-generate-png
done
```

## Profile photo

`photo/face1.jpg` is the owner's face and is used in **every** CV. It is referenced in
three different ways, depending on the file type — keep all of them in sync when the
photo changes:

| Where | How it's referenced |
|-------|---------------------|
| RenderCV YAML | `photo: ../photo/face1.jpg` (path is **relative to the YAML file** in `rendercv/`) |
| `cpp-engine-cv.html` | `<img src="photo/face1.jpg" ...>` (relative to repo root) |
| `reactive_resume.json` | base64 **data URI** in `picture.url` (Reactive Resume expects a data URI/URL, not a file path) |

If you replace `face1.jpg`, re-render the PDFs and re-embed the data URI in the JSON.

## Conventions for editing

- YAML indentation is **2 spaces**; preserve the existing `design:` block (theme
  `engineeringclassic`, A4 page, custom margins/typography) unless explicitly asked.
- The photo uses RenderCV header defaults (3.5 cm wide, left of the header). Width and
  position are controlled by `design.header.photo_width` / `photo_position`.
- Dates are `YYYY-MM` in the YAML sources.
- Keep `reactive_resume.json` as the master: if you change a fact (e.g. a job date),
  update it here first, then propagate to the three YAML files.
